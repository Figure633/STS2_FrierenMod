# 机制与交互规范

版本：v0.1；日期：2026-10-17。本文的“二代规则”是拟采用的实现契约；旧实现歧义在文末单列。单张牌的特殊效果优先通过显式修饰器扩展通用规则，不散落例外判断。

## 1. 术语与状态归属

| 术语 | 定义与边界 |
|---|---|
| 能量 | 游戏原有出牌资源，不能与魔力牌数量或菲伦充能混同 |
| 魔力 | 具有 Mana 语义标签的卡牌实例；身份不依赖中文名称或卡面图 |
| 魔法因子 | 独立收藏中的规则实体；装入一个槽后可由咏唱激活 |
| 魔法道具 | 独立收藏中的一次性或规则定义的物品；不是可装载因子 |
| 槽位 | Draw/Hand/Discard 三个稳定枚举，对应抽牌/手牌/弃牌区；未装载为 None |
| 牌堆外区域 | 封印、处理中、选择预览等；不参与通用魔力总数 |
| 咏唱牌打出 | 本回合打出具有 Chant 标签的牌，用于传说魔法等条件 |
| 咏唱操作完成 | 一次合法咏唱指令完成，可能激活一个或多个因子 |
| 因子激活 | 一个指定槽位的因子支付并执行效果；与咏唱操作计数分别维护 |
| 融合 | 待应用到下一张符合条件的特化普攻魔法的效果队列 |

运行时分为玩家局内状态、玩家战斗状态、回合状态和纯 UI 状态。存活于哪一层必须显式声明，不能用静态字段承载所有角色的数据。

## 2. 三槽与魔法物品

SLOT-01：每名芙莉莲有独立收藏和三个槽；每槽最多一个因子实例，同一实例不能占两个槽。允许同类型不同实例出现在不同槽，具体获取规则不得被 UI 去重误删。

SLOT-02：开局按抽牌槽、手牌槽、弃牌槽完成选择。每轮候选去重、合法、种子确定；确认后添加到收藏并装载。保存已经确认的步骤与待选候选，恢复不重抽，不重复添加。

SLOT-03：装载、卸载和替换只能在规则允许的安全操作窗口执行。普通界面在动作结算、目标选择、奖励选择等未完成时为只读；卡牌效果要求中途调整槽位时，作为队列中的显式操作处理。这是二代的确定性适配决定，不声称复刻旧 UI 的所有点击时机。

SLOT-04：装载变更是原子事务：先验证拥有关系、槽位类型和目标实例，再提交变更并刷新预览。失败不丢失旧装载，不复制收藏。

SLOT-05：蓝图式复制需要解析最终非复制因子；遇到循环、空槽或无终点返回“当前无法咏唱”的有类型结果。不得解引用 null、无限递归或悄悄指定另一个槽。

## 3. 魔力与咏唱

### 3.1 计数与支付

只计入本人抽牌堆、手牌和弃牌堆中的 Mana 实例。消耗堆可供特定回收牌读取，但不计入 `TotalUsableMana`。魔力被咏唱支付属于“消耗”，不等于“打出”，因此不会自动触发一次同调、打牌计数或耗能。

无其他特殊效果时，槽位所需魔力：

`requiredMana = max(0, chantX × factorMultiplier + factorOffset − concentration + weakenedChant)`

存在明确免魔力效果时，最终支付为 0；次数型免除在本次合法操作提交时消耗一次，不能在预览时消耗。是否按因子或按整次操作消耗由效果契约声明，默认按咏唱操作一次。以上统一免费咏唱可用性与实际扣费，是二代明确修正。

因子的基础收益从 `chantX × rewardMultiplier + rewardOffset` 得出，再按效果类型进入目标游戏伤害、格挡和能力管线；不能把所有收益都当最终伤害直接扣血。所有参数、取整方向和上下界由同一个规则函数提供给 UI 与执行层。

### 3.2 操作事务

1. 校验操作者、当前回合、动作窗口、咏唱牌条件和可用目标。
2. 从当时状态建立候选槽及费用/效果预览。禁止无候选时打开无法退出的选择框。
3. 玩家选择槽；提交包含玩家 ID、操作 ID、槽和状态版本的选择。
4. 再验证候选仍合法。若未提交可取消；已提交出牌不能借 UI 取消免费撤销已付的游戏费用。因状态变化失效时，走明确失败分支且不额外扣魔力。
5. 在对应牌堆按稳定顺序确定要消耗的具体实例，记录支付清单；支付期间不再次任意扫描不同的牌。
6. 通过游戏命令消耗这些实例，依次执行因子效果、每因子后置事件和整次咏唱完成事件。
7. 解除选择锁，清理操作临时对象；失败、战斗结束和玩家失效均有终止路径。

重发同一操作 ID 不得再次支付或触发。UI 关闭不等于逻辑回滚。实际游戏自动打出行为若绕过通常条件，需要独立契约与测试，不能假定它等于手动打出。

### 3.3 普通、精准、终极咏唱

| 类型 | 二代约定 |
|---|---|
| 普通 | 使用卡牌定义的 X，从合法槽中选择一个 |
| 精准 | 每槽计算可支付的最大合法 X，再选择一个；必须沿用同一费用计算器处理专注、弱化、取整与上限 |
| 终极 | 从提交时状态确定各槽 X 与顺序，按 Draw→Hand→Discard 激活合法因子；每因子事件各一次，整次完成事件一次 |

精准/终极的免费咏唱不能求得无限 X。二代默认以“关闭免付标志、保留其他修饰”时可支付的最大 X 决定规模，随后应用免费支付；X≤0 的槽不可用。这是需在专门偏差记录中验证体验的适配规则，不能引用为一代原行为。

解析复制因子后要使用该因子的费用与收益系数，且要求费用倍率大于 0；不合法数据必须在内容校验阶段报错。

## 4. 同调与传说魔法

| 标签组合 | 结算 | 去向 |
|---|---|---|
| 同调 | 抽 1 张 | 使用后消耗 |
| 加速同调 | 抽 2 张 | 使用后消耗 |
| 终极同调 | 随机对一名合法敌人造成基值 15 的特殊伤害 | 使用后消耗 |
| 终极加速同调 | 上述伤害，然后抽 2 张 | 使用后消耗 |

组合按最高匹配分支执行一次，不额外叠加普通同调抽牌。伤害必须保留原 `AttackSpecialDamageRandomEnemyAction` 的伤害类型及修饰语义，需逐项对照确认；表中 15 不表示最终无视防御伤害。没有合法敌人时不进行随机选择；战斗已结束时遵从引擎队列终止规则。

传说魔法默认要求本回合已打出咏唱牌，而不是任意代码触发过因子；明确豁免遗物按其持续期生效。回合计数按玩家维护，回合开始重置。若一张牌同时具有咏唱和传说标签，入场合法性不能把自己尚未打出的事件计入条件。

依据：[SynchroAction.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/actions/SynchroAction.java)、[SynchroMod.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/cardMods/SynchroMod.java)、[CombatHelper.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/gameHelpers/CombatHelper.java)。

## 5. 菲伦规则

FERN-01：专注为独立能力值；默认非魔力且非疾速牌的打出效果完成后减少 1，最低值遵循能力是否允许负数的明确规则，本模组默认不因该衰减低于 0。咏唱的减耗和菲伦奇袭读取同一语义的专注数值。

FERN-02：奇袭在卡牌效果中的规定时点判定，默认 `concentration == raidX`，不是 `>=`。正常奇袭牌在本次打牌后衰减前判定；改变窗口、额外次数、伤害专用额外次数分别由修饰器计算。每次触发事件与整次奇袭完成事件分开，不把每个伤害段都当一次奇袭。

FERN-03：法杖充能独立于能量与专注。默认最大充能 1、每回合刷新；卡牌/遗物变更上限或倍率应同步保存规定层级的状态。通过按钮、快捷键或手柄动作发起同一规则指令，不在绘制函数里扣值。

FERN-04：生成特化普攻前预览本次专注 × 倍率及待融合效果；确认后锁定参数、消耗 1 充能、按规则清除专注并生成卡。手牌满时采用目标游戏明确的生成牌溢出规则，必须在 UI 说明且测试；不得吞掉卡后仍静默消耗资源。

FERN-05：融合状态只被下一个符合条件的生成动作消费一次。复制预览、打开卡牌图鉴、切换语言不得消费。多个融合项按稳定顺序合并；复制生成牌必须复制值对象，不能共享可变效果集合。

依据：[ConcentrationPower.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/powers/ConcentrationPower.java)、[FernPanel.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/ui/panels/FernPanel.java)。

## 6. 其他机制契约

| 机制 | 必须规定的行为 |
|---|---|
| 解析 | 在手牌中满足对应条件后，减少剩余次数、发放一次奖励并刷新条件；次数为 0 时消耗；一次条件事件不得被多次监听重复结算 |
| 封印 | 战斗开始置于专用区域；按原关键词基线，本回合打出 5 张咏唱牌后解封；目标手牌满、自动打出和战斗结束有明确处理 |
| 回火 | 本回合每次打出该实例后费用 +1，下个回合恢复该牌的正确基础/永久修饰费用；不能抹掉永久升级 |
| 魔力代能量 | 使用统一支付入口；费用为 X、0、不可打出、免费出牌和减费后的值分别测试；禁止既扣能量又扣魔力 |
| 因子掉落 | 保留普通/精英等战后获取途径与修正状态；源码基础概率为普通战斗/事件战斗 40、精英 70，中奖修正 -10、未中奖 +10；二代按房间语义适配并夹到 0～100，有单独 RNG 流 |
| 自定义魔导书 | 每层选择写入组合蓝图；升级、复制、描述生成与恢复从同一蓝图重建，不序列化任意运行时类名 |
| 时间观念 | 先形成专门的快照字段表、触发回合、升级行为、不回溯项和事件重放规则；未完成前该牌不进入公开可获取池，也不能据此宣布 1.0 完整 |

封印等关键词依据：[ZHS keywords.json](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/resources/FrierenModResources/localization/ZHS/keywords.json)。掉落基线依据：[HookHelper.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/gameHelpers/HookHelper.java)。

## 7. 交互规范

- 三槽选择按抽牌、手牌、弃牌顺序固定显示，展示因子、X、需要/现有魔力、预计收益和不可用原因。颜色只作辅助。
- 魔法物品界面区分收藏、已装载和道具，提供筛选与详情；战斗只读状态要有说明。关闭后返回原界面，不丢失其选择上下文。
- 菲伦法杖面板同时显示当前/上限充能、专注、生成牌预览；键鼠、手柄走相同确认逻辑，避免必须右键才能使用。
- 首次教程解释魔力不是能量、咏唱消耗来自所选槽对应牌堆、同调消耗与咏唱消耗的差别。可跳过、可在帮助中重看。
- 对资源不足、循环蓝图、失效目标、队列忙和不支持的模式给出短而具体的提示，不暴露内部异常栈。
- 普通关闭/返回不默认选取随机候选；必须选择的流程提供清晰的继续条件，不允许绕过未提交的必要初始化。

## 8. 单项内容规格模板

每张卡、因子、遗物、药水、事件和怪物在实现前建立记录，至少包含：旧 ID 与固定源码链接、二代稳定键、显示名、获取池、基础/升级数据、触发时点、目标和支付规则、效果顺序、计数作用域、复制/移除/保存行为、资源与本地化键、适配偏差、测试用例编号、当前状态。

[content.json](inventory/content.json) 提供旧来源和初始数据，尚不包含所有升级代码的语义解析。禁止将其中的静态字段抽取误当完整规则规格。

## 9. 必须在扩展阶段关闭的歧义

免费咏唱可用性与扣费不一致、精准/终极的最大 X、终极咏唱重复回调、蓝图循环、时间快照范围，以及一代特定敌人相关效果，均进入 [风险台账](06-决策与风险台账.md)。新规则已有默认边界的按本文执行；需要一代运行录像或二代能力验证才能定案的项，不以猜测补齐“已验证”状态。
