## 建议落地方式（待代码重构）

- 初期保留一个模组工程和统一入口；在代码层区分 Frieren、Fern、Shared。角色内部按 Cards、Powers、Relics、Mechanics 等职责组织，普通卡牌再按稀有度拆分。
- 芙莉莲与菲伦分别拥有角色定义、起始牌组、卡池、遗物池、专属机制和展示资源。跨角色共用基类不携带芙莉莲专属 Pool 属性。
- 共享卡牌抽取共用行为，具体卡池归属依据一代行为和二代注册接口确认；不能仅因放入 Shared 目录就自动加入两边奖励池，避免重复注册与奖励权重异常。
- 共用能力按实际语义决定归属；菲伦专属法杖等状态独立管理。所有局内状态明确所属玩家，避免静态字段串角色或串玩家。
- 迁移目录时保留现有模型身份、存档键、本地化键和资源引用，若确需改变需提供迁移与验证。
- 保留纯规则层及现有测试体系；新增角色时核验角色选择、卡池隔离、共享内容、存读档、界面和资源。目录预留不等于已经实现角色或联机支持。
