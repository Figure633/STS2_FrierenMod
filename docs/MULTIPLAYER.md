# 多人适配

0.10.0 的魔具使用、初始三次因子选择及营地魔具店接入原生多人流程。玩家仍各自拥有魔法书；双方需使用相同版本的模组和 BaseLib。

- `NetMagicDeckAction` 由原生 `ActionTypes` 自动发现，经过原生动作信封、房间消息缓冲与主机排序。玩家身份来自信封，不接收包内指定的其他玩家。
- 魔具请求携带实例 ID、目标 ID、库存 SHA256 快照、战斗状态和本人回合编号。各端在相同队列位置验证并结算；无效、重复、过期请求不消费物品或 RNG。
- 随机魔具使用所属玩家 `PlayerRng.Rewards`，所有端执行同一规则。游戏数据不等待本机动画。
- 营地仍通过 `RestSiteSynchronizer` 消费行动；其选牌结算进入同一动作队列，使用 `GameActionPlayerChoiceContext` 和原生 `CardSelectCmd`。取消选择不消费行动。远端不读取本机覆盖层或输入忙碌状态。
- 多人保留原版涅奥，芙莉莲通过同步动作独立完成三次初始选择并各领两个工具。教程只在本机显示。单人的原魔导书事件保留。
- 混合队伍沿用现有原版事件和 Boss 池；全芙莉莲队伍沿用专属内容资格。此批未更改专属 Boss 的玩法设计。
- 魔具只在所属角色存活且处于其出牌阶段时可用于战斗，其他角色的额外回合不会开放本人的操作。断开或退出跑局时结束本机等待任务；重建玩家对象后从原生存档恢复魔法书。

## 本机验证

先按通常入口构建打包，再构建 `Tests/Engine/EngineTests.csproj`，执行：

```powershell
pwsh -NoProfile -File tools/run-multiplayer-check.ps1
pwsh -NoProfile -File tools/run-multiplayer-check.ps1 -Mixed
```

脚本启动两个独立、隐藏的 Godot 进程，经真实回环 ENet 连接使用原生消息总线、动作队列与选择同步器。测试仅代替选牌屏的人工点击，不替换 `CardSelectCmd` 或网络结果。每阶段比较双方视角中的全部玩家库存、RNG、生命、能量、牌堆和能力。

覆盖独立初始因子与赠品、营地确认/取消、魔具和商店交错请求、八种魔具、重复/非法/过期请求、本人出牌阶段与死亡限制、原生出牌包、时空门独立机会、完整跑局网络序列化，以及重建 ENet 连接后经 `SetUpSavedMultiplayer` 恢复并继续操作。

原生营地菜单、跨幕、Steam 大厅加入/重入、真实界面整局与公网延迟下的表现仍需游戏实测；本机自动验证不等于这些流程已经验收。日志写入 `artifacts/multiplayer/`，不读取或覆盖作者的游戏存档。
