## 3. 角色与核心系统

### 3.1 芙莉莲

源码初始值为 75 生命、99 金币、每回合 3 能量、5 抽牌；初始牌组是 4 张 `Strike_Frieren`、3 张 `Defend_Frieren`、各 1 张 `Flow`、`DefensiveMagic`、`RapidChant`，共 10 张；初始遗物 `HolyEmblem`。

核心循环为：生成/移动魔力牌 → 配置对应抽牌、手牌、弃牌的三个槽 → 咏唱选择因子 → 从对应牌堆消耗魔力 → 触发效果与后续联动。独立魔法物品收藏与普通卡组分开维护。读魔导书开局流程逐槽给出三选一，不能省略后直接让玩家进入缺槽战斗。

其他系统包括同调及变体、传说魔法、解析、封印、回火、魔力代替能量、因子掉落、道具、槽位外观成就、自定义魔导书、精灵时间观念。

依据：[Frieren.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/Characters/Frieren.java)、[ReadingGrimoireEvent.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/events/ReadingGrimoireEvent.java)、[CombatHelper.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/gameHelpers/CombatHelper.java)。

### 3.2 菲伦

源码初始值同样为 75 生命、99 金币、3 能量、5 抽牌；初始牌组是 4 张 `Strike_Fern`、4 张 `Defend_Fern`、`CriticalHit`、`LieInWait`；初始遗物 `HairAccessory`。

专注在非魔力且非疾速牌结算后递减；奇袭默认要求专注恰好等于 X，有能力可以改变判定范围或触发次数。融合把效果附加到下一张获得的特化普攻魔法。法杖面板提供独立充能及主动生成卡牌入口；默认基础倍率为专注 × 2，使用 1 次面板充能并清除专注，回合刷新充能。不能只移植紫色卡牌而遗漏面板。

依据：[Fern.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/Characters/Fern.java)、[FernPanel.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/ui/panels/FernPanel.java)、[PanelPatch.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/patches/PanelPatch.java)。

### 3.3 事件与怪物

明确注册事件为 `FoodEvent`、`KraftGift`、`AnimalWell`、`MimicFight`。`ReadingGrimoireEvent` 经开局特殊流程进入，不是普通事件池中的第五个随机事件。怪物/首领入口包括 `Mimic` 与 `Spiegel_Frieren`。旧章节 ID、尼奥事件、敌人名单和移除时间吞噬者配置需要映射到二代语境。

依据：[RegisterHelper.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/utils/RegisterHelper.java)、[ReadingGrimoireEventPatch.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/patches/ReadingGrimoireEventPatch.java)。

## 4. 已识别的历史内容与疑点

| 项目 | 已核查事实 | 二代处理 |
|---|---|---|
| 角色交换 | `CharacterExchanger`、`Exchange`、`ExchangeBack` 全注释 | 不作为一代正式功能；不纳入默认范围 |
| 修塔尔克 | 默认关闭，只有 2 个 orange 卡文件 | 后续扩展，不宣称完整角色已存在 |
| 旧遗物/牌 | `HaitaaWand`、`OLDHairAccessory`、`FrushDown`、`PaperPlaneSpell`、`MysticEye`、`BloodSpell` 显式忽略 | 保留审计记录，不默认复活 |
| `TODO.txt` | 混有勾选事项、历史平衡提案和未实现创意 | 只作历史参考，需求以活动实现和本次决策为准 |
| 免费咏唱 | `getManaNeedBeforeLoaded` 不检查免魔力能力，`getManaNeedWhenLoading` 检查 | UI 可选判断与实际扣费存在静态不一致，需最小复现 |
| 蓝图全装载 | `getChantChoices` 在全蓝图时返回 null，调用方存在直接访问 | 增加空槽/循环复制的显式不可用结果 |
| 终极咏唱 | 分支另行触发回调，而因子选择本身也会触发回调 | 记录一次操作与多个因子执行的事件边界，不能直接复制触发次数 |
| 存档 | `DataObject.load` 解析后只打印 map，未见写回成员 `dataMap` | 静态缺陷线索，需检查整体调用链；二代必须独立设计并测试保存恢复 |
| 时间观念 | 快照含玩家牌堆、能力、药水和遗物；`maxEnergy` 读取了 `maxOrbs` | 高风险重写，不能照搬反射克隆或疑似错误字段 |

以上是静态审计发现，不宣称已经在一代游戏中复现。来源：[DataObject.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/gameHelpers/DataObject.java)、[ChantAction.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/actions/ChantAction.java)、[TimeTravelAction.java](https://github.com/FrierenModForSlayTheSpire/FrierenMod_STS1/blob/8604c9cd072dba6ae1bf8f47986fdc291b26c3cc/src/main/java/FrierenMod/actions/TimeTravelAction.java)。

## 5. 资源与语言

仓库 `src/main/resources/` 有 961 个文件：867 PNG、24 MP3、10 OGG、2 atlas、58 JSON。仅枚举远程资源树，没有为本次文档下载全部二进制资源。本地素材含这些资源的候选副本，后续需按内容路径与哈希对齐；本次仅比对了 Java 源码。

存在 ZHS、ZHT、ENG、JPN、KOR、RUS 六套本地化目录，各 9 个 JSON 均可解析，但键集合不同。例如卡牌条目分别为 242、240、239、242、242、239；这不是六套语言都完整可用的证明。[语言差异表](inventory/locale_gaps.json) 已生成。

Word、Excel、PSD 本轮仅登记路径和大小，未打开内部内容。它们可以作为高清图、历史数值和排版参考，不覆盖固定提交的玩法基线。美术、音乐与其他贡献者来源在资源接入时逐项登记；保留仓库现有许可证与署名。

## 6. 二代技术依据

本轮检查社区维护者 Alchyr 的 [角色模组模板](https://github.com/Alchyr/ModTemplate-StS2) 固定提交 `2c900a04dd2073872f677f4fb78ee2ad1e871009`：角色模板使用 `Godot.NET.Sdk/4.5.1`、`net9.0`、游戏程序集引用和 BaseLib；清单示例包含 `min_game_version=0.107.0`、BaseLib 最低版本 `3.3.0`。**这些是模板声明，不是本项目兼容性承诺。**

维护者 [安装说明](https://github.com/Alchyr/ModTemplate-StS2/wiki/Setup) 建议使用 Mega Crit 的 MegaDot、相应 .NET SDK 和 BaseLib。BaseLib 是社区依赖，参考入口见 [BaseLib 仓库](https://github.com/Alchyr/BaseLib-StS2)。本项目选择 C# / Godot / BaseLib 路线，G0 必须用用户实际安装的游戏版本验证后冻结工具链。
